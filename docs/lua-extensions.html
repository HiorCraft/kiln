Entwurf · kiln Extensions v1

So könnten Lua-Module aussehen

Ein Server liefert neben Texturen auch kleine Lua-Skripte aus. Der Client lädt sie beim Join, fragt einmal nach Zustimmung und führt sie in einer Sandbox aus. Die Skripte sehen nur die kiln-API, nie Minecraft, Java oder das Dateisystem.

Ablauf beim Join

1 · Manifest

Server schickt Liste der Extensions mit Version und SHA-256.

2 · Cache

Client lädt nur, was er noch nicht im Cache hat, und prüft den Hash.

3 · Zustimmung

Einmal pro Server: Name, Rechte (z. B. HUD, Tasten) anzeigen, Spieler bestätigt.

4 · Sandbox

Jede Extension bekommt eine eigene Lua-Umgebung mit Limits für Speicher und Rechenzeit.

5 · Disconnect

Beim Verlassen werden alle Umgebungen, Tasten, Widgets und Texturen entfernt.

Aufbau einer Extension

Eine Extension ist ein Ordner bzw. ein Zip mit Manifest, Lua-Dateien und Assets. Der Server legt sie unter plugins/Kiln/extensions/ ab oder ein Plugin registriert sie per API.

  • permissions listet, was das Skript darf. Der Client zeigt das bei der Zustimmung an.
  • Texturen landen im eigenen Namespace und gelten nur, solange man auf dem Server ist.
  • Kein require von außen: nur Dateien aus dem eigenen Paket.
factory/extension.json
{
  "id": "factory",
  "version": "1.2.0",
  "name": "Factory-Anzeigen",
  "main": "main.lua",
  "permissions": ["widgets", "keybinds", "hud", "channels"],
  "assets": ["textures/gauge_bg.png", "textures/icons/*.png"]
}

Beispiele

Eigenes Widget: Gauge

Ersetzt das Kotlin-Gauge aus dem Example-Client. Der Server nutzt es wie bisher als custom("factory:gauge") und schickt nur value und label.

  • g ist ein Zeichenkontext mit wenigen Befehlen: Rechteck, Linie, Bogen, Text, Textur, Item.
  • Animation läuft lokal: shown nähert sich dem Server-Wert pro Frame an.
factory/main.luawidgets
local ui = kiln.ui

ui.widget("factory:gauge", {
  -- Zustand pro Widget-Instanz, bleibt über UpdateScreen erhalten
  init = function(self)
    self.shown = 0
  end,

  render = function(self, g, w)
    local target = w.props.value or 0
    self.shown = self.shown + (target - self.shown) * 0.2

    local cx, cy = w.width / 2, w.height - 20
    g:texture("factory:textures/gauge_bg.png", 0, 0, w.width, w.height)
    g:arc(cx, cy, 18, 6, 0, 1, 0xFF2A2F2C)
    g:arc(cx, cy, 18, 6, 0, self.shown, ui.lerpColor(0xFFC0503A, 0xFF5FBF5A, self.shown))
    g:text(string.format("%d%%", math.floor(self.shown * 100)), cx, cy + 2, { align = "center" })
    g:text(w.props.label or "", cx, w.height - 9, { align = "center", color = 0xFFCCCCCC })

    if w.hovered then
      ui.tooltip(w.props.label .. ": " .. math.floor(target * 100) .. " %")
    end
  end,

  click = function(self, w, button)
    return true -- Klick als ScreenClick an den Server melden
  end,
})

Taste und typisierter Kanal

Das Gegenstück zum heutigen Example-Client in wenigen Zeilen. Die Taste erscheint im Steuerungsmenü unter dem Server, die Belegung merkt sich der Client.

  • Kanäle sind automatisch im Namespace der Extension (factory:hello).
  • Nachrichten sind Lua-Tabellen, kodiert als kompaktes JSON. Größe und Rate sind begrenzt.
factory/main.luakeybinds, channels
local net, keys, ui = kiln.net, kiln.keys, kiln.ui

local hello = net.channel("hello")

keys.bind("hello", {
  name = "Hallo an Server",
  default = "J",
  press = function()
    hello:send({ text = "Hallo vom Client!" })
  end,
})

hello:on(function(msg)
  ui.toast("Server", msg.text)
end)

HUD-Overlay

Zeichnet dauerhaft eine Maschinen-Anzeige ins Spiel, ohne Screen. Der Server schickt den Zustand nur bei Änderungen, die Animation dazwischen macht der Client.

  • Nur mit Recht hud. Das Overlay bekommt einen festen Bereich und kann keine Vanilla-Anzeigen verdecken.
  • kiln.time() liefert Spielzeit, keine Systemzeit.
factory/hud.luahud, channels
local hud, net = kiln.hud, kiln.net

local state = { energy = 0, running = false }
net.channel("machine"):on(function(msg) state = msg end)

hud.layer("machine", { anchor = "top_right", width = 90, height = 22 },
  function(g, area)
    if not state.running then return end
    local pulse = 0.5 + 0.5 * math.sin(kiln.time() * 4)
    g:rect(0, 0, area.width, area.height, 0xA0101410)
    g:item("minecraft:blast_furnace", 3, 3)
    g:rect(22, 8, 64, 6, 0xFF2A2F2C)
    g:rect(22, 8, 64 * state.energy, 6, ui.alpha(0xFFE3C26B, 0.7 + 0.3 * pulse))
  end)

Client-Logik in einem Server-Screen

Für Dinge, die ohne Latenz reagieren müssen: Items per Drag & Drop in einem Sortier-Raster verschieben. Der Client zeigt das Ergebnis sofort, der Server bestätigt oder setzt zurück.

  • Das Skript ändert nur seine eigene Darstellung. Echte Items bewegt immer der Server.
  • Lehnt der Server ab, kommt ein normales UpdateScreen, und die Vorschau verschwindet.
factory/sorter.luawidgets, channels
local ui, net = kiln.ui, kiln.net
local move = net.channel("sorter_move")

ui.widget("factory:sorter", {
  init = function(self) self.drag = nil; self.preview = {} end,

  render = function(self, g, w)
    for i, item in ipairs(w.props.items) do
      local slot = self.preview[i] or i
      local x, y = ((slot - 1) % 9) * 18, math.floor((slot - 1) / 9) * 18
      if self.drag ~= i then g:item(item, x, y) end
    end
    if self.drag then
      g:item(w.props.items[self.drag], w.mouseX - 8, w.mouseY - 8)
    end
  end,

  press = function(self, w, mx, my)
    self.drag = ui.cellAt(mx, my, 18, 9)
  end,

  release = function(self, w, mx, my)
    local to = ui.cellAt(mx, my, 18, 9)
    if self.drag and to then
      self.preview[self.drag] = to            -- sofort anzeigen
      move:send({ from = self.drag, to = to }) -- Server entscheidet
    end
    self.drag = nil
  end,
})

Serverseite in Kotlin

Plugins registrieren ihre Extension und nutzen die Widgets wie eingebaute Elemente. Kanäle sind typisiert, damit kein ByteArray-Handling mehr nötig ist.

  • Spieler ohne Zustimmung oder ohne Runtime: hasExtension ist false, das Plugin wählt einen Fallback.
FactoryPlugin.kt
val factory = kiln.extension(this, "factory") {
    source(dataFolder.resolve("extensions/factory"))
}

val hello = factory.channel<HelloMessage>("hello") { player, msg ->
    send(player, HelloMessage("Hallo zurück, ${player.name}!"))
}

player.openScreen(220, 120) {
    if (player.hasExtension(factory)) {
        custom("gauge", factory.widget("gauge"), width = 40, height = 40) {
            property("value", machine.energy)
            property("label", "Energie")
        }
    } else {
        progressBar(machine.energy, width = 100)
    }
}

Was ein Skript darf

Die Sandbox ist LuaJ ohne gefährliche Standardbibliotheken. Alles, was ein Skript bewirken kann, läuft über die kiln-API.

BereichVerfügbarHinweis
Lua-Basis: string, math, table, pairsjaohne string.dump
Zeichnen in eigenen Widgets und HUD-Layernjanur im zugewiesenen Bereich, mit Clipping
Eigene Kanäle zum Server, von dem die Extension kamjaGröße und Rate begrenzt
Keybinds, Toasts, Tooltipsjanur mit passendem Recht im Manifest
Lesender Zugriff auf Spielerposition, Inventar, ZeitjaKopien, keine Minecraft-Objekte
io, os, debug, load mit Bytecode, luajavaneinwerden beim Start entfernt
Netzwerk zu anderen Hosts, Dateien, Prozesseneinkeine API dafür vorhanden
Chat mitlesen, Session, Serverliste, andere Modsneinkeine API dafür vorhanden
Vanilla-Screens überlagern oder imitierenneinEscape schließt eigene Screens immer

Grenzen pro Extension

2 msRechenzeit pro Frame, gezählt über Instruktionen
16 MBLua-Speicher

40 / sKanal-Nachrichten an den Server

Überschreitet eine Extension ein Limit, wird sie entladen und der Spieler bekommt einen Hinweis. Der Rest des Servers läuft normal weiter. Die Werte sind Vorschläge für den Prototyp.
